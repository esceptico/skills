# Lessons

- UI for the user's tools: start from Arden's design system (`~/src/ntrp/apps/desktop/src/design/base.css`) instead of inventing styling. Avoid a thick left border on rounded boxes; it renders as a curved bracket. Use soft tinted pill rows instead.
- "Review the skills" means review their content: instructions, triggers, gaps, contradictions. Not where they are installed, repo layout, or frontmatter conventions, unless asked.
- Put the review itself in the message before any wrap-up question; a wrap-up that asks a question ends the turn and the user never sees findings left for "after".
- "Commit and push" after a review covers every skill reviewed. A skill that lives outside the repo (e.g. ~/.codex/skills) gets copied into skills/ and the README first; do not leave it behind and report it as "outside the repo".
